## 3. Рекомендации по задачам и эпикам

Приоритеты для выхода в прод и ближайшего пост-прода.

### 3.1 Перед первым прод-запуском (P0)

- **EPIC 2 (Testing):** ввести тестовый раннер и интеграционные тесты на: incoming worker (ingest → processed/failed), outbox (profile_transferred_to_buyer → processed), state transitions (reclaim, guard), при необходимости — queue acquire/release.
- **Health/readiness:** реализовать проверку БД (и при необходимости MQTT) в `/health` или `/ready`, возврат 503 при недоступности; при старте приложения — fail-fast при недоступности main DB.
- **Секреты:** убрать дефолтный `QUEUE_API_KEY` для production (env-переменная обязательна в проде).
- **Документ runbook:** перечень env-переменных для прода, порядок применения миграций, что проверять при деплое (health, логи воркеров, метрики при наличии).

### 3.2 Сразу после выхода в прод (P1)

- **EPIC 6 (MQTT):** довести MqttClient до уровня platform module (publish-буфер при disconnect, subscription registry, при необходимости wildcard) — см. implementation_progress.md § T1.2.
- **EPIC 8 (CardOwnershipService):** собрать единый доменный слой владения (запросы «кто владел в момент X», все операции через сервис) — закрывает архитектурный риск.
- **Outbox:** явная политика для неизвестного `event_type` (failed + алерт или allow-list).
- **Drafts:** реализовать buyer_email через Farm DB, если матчинг выписок с draft критичен.

### 3.3 По бэклогу эпиков (после стабилизации)

- **EPIC 3.3:** автоматический переход в `dead_letter` для statement_import_jobs при повторных неудачах (или ручной процесс + runbook).
- **EPIC 7:** полный workflow drafts (lifecycle, TTL, оба типа payload).
- **EPIC 9:** обогащение транзакций, fallback matching (drafts/aff_id).
- **EPIC 10:** единый стандарт валидации API и обработки ошибок (схемы, централизованный маппинг).
- **EPIC 13:** консолидация дублей (statements_import → statementsImport), naming governance, module README.
