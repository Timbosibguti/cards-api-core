## 3) Текущее техническое состояние

### Архитектура и исполнение

- Используется модульная структура (`api`, `infra`, `modules`) с единым bootstrap.
- Fastify-сервер поднимает широкий набор роутов (health, webhooks, queue, statements, cards, events ingest, card block и пр.).
- Runtime построен на воркерах с паттерном `SELECT ... FOR UPDATE SKIP LOCKED`, что хорошо для конкурентной обработки.
- Есть graceful shutdown для HTTP, MQTT, воркеров и БД.

### Надежность пайплайна

- Outgoing-воркер имеет retry/backoff и перевод статусов в БД.
- Есть stuck/reclaim job для возврата зависших записей в `pending` или перевод в `failed`.
- Обработка нотификаций централизована через `outgoing_notifications`, что снижает разброс side-effects.
- Для потока unlink-dead зафиксирован MR29-процесс: перед отвязкой карты от мертвого профиля выполняется `adapter.blockCard`; при ошибке провайдера строка `bank_cards` не меняется и операция повторяется в следующем прогоне.

### Тестируемость

- Фактически есть только один тестовый файл (14 unit-тестов на state transitions).
- Проверка типизации проходит.
- Интеграционные сценарии для ключевых потоков (webhook -> DB -> outgoing -> delivery) в текущем срезе не представлены.

## 6) Основные риски и зоны внимания

1. **Ограниченное покрытие тестами**  
   Сейчас тестируется только модуль переходов статусов; нет достаточного покрытия бизнес-критичных интеграций.

2. **Безопасность JWT в `src/infra/jwt.ts`**  
   Реализован `decode` без верификации подписи токена (по комментарию это осознанная совместимость). Это приемлемо только в строго доверенном контуре; при расширении периметра риск подмены payload высокий.

3. **Операционная сложность runtime**  
   Большое число независимых циклов в одном runtime-файле увеличивает нагрузку на сопровождение и сложность диагностики инцидентов.

4. **Документированные архитектурные долги**  
   По текущей документации остаются открытыми темы централизации ownership-домена и дальнейшего укрепления MQTT/platform-слоя.

5. **Риск секретов в рабочем дереве**  
   В корне присутствуют `.env`/`.env.local`/`.env.prod`. Даже если это локальный контур, нужно строго исключать утечки в VCS и артефакты доставки.
