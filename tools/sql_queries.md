Инструкции по запросам SQL Sequoia

- Все работы с профилями производятся в схеме farm_ext (если не указано иное)
- Если запросы касаются профилей , привязки профилей к фармерам или байерам, то искать надо в схеме farm_ext. Профили в таблице farm_ext.tbl_profiles. Статусы и фазы профилей искать в таблицах farm_ext.tbl_statuses, farm_ext.tbl_phases. 
- Профиль находится у фармера, если есть запись в таблице farm_ext.tbl_profile_access_grant с флагом lock_exclusive=true.
- Профиль принаджелит байеру если в farm_ext.tbl_profiles auth_id нет активной записи в farm_ext.tbl_profile_access_grant
- Если запросы касаются организационной структуры компании, должностей, то это схема finance1_ext. Таблица сотрудников это employees. Отделы компании - таблица departments, Филиалы байеров - таблица branches
- auth_id - это id пользователя из таблицы farm_ext.tbl_users. Этот же ИД пользователя в Retool. Искать данные о пользователе с  auth_id в таблица  tbl_users (схема farm_ext)

# Работа с профилями
- Статусы профилей tbl_profiles.status_id, таблицы farm_ext.tbl_statuses, farm_ext.tbl_phases, farm_ext.tbl_stages
- если у профиля status_id 10 (Фармится) и по задаче нужно менять статус на другой или выдать байеру, то необходимо также снять флаг lock_exclusive в таблице tbl_profile_access_grant для этого профиля с этим profile_id.
- нельзя предлагать запросы на удаление записей из tbl_profile_access_grant таблицы. можно только lock_exclusive=false делать 
- Профиль может быть у байера или у фармера или свободным. Не использовать tbl_user_groups для определения владельца профиля
- Историю действия с профилей (смена его статусов) надо смотреть в таблице tbl_statuses_log
- Если на вход подается CSV файл и задача связана с массовым поиском или обновлением профилей из этого списка, то используй скрипт csv_to_where.py для преобразования столбцов в фильтр WHERE для postgress. 


# Определение владельца профиля (Фармер, Фиксер, Байер)
- Каждый профиль в системе может быть: Свободным (не назначен никому), у фармера/фиксера в работе или у байера.
- Фиксеры тоже относятся к Фарм отделу. Фармер и фиксер могут интерпретироваться как синонимы. Фиксеры обычно подключаются к профилям, которые уже ранее были выданы байерам
- Для принадлежности профиля фармеру или фиксеру Смотреть farm_ext.tbl_profiles.auth_id, farm_ext.tbl_profile_access_grant (поля auth_id, profile_id, lock_exclusive bool )
- tbl_profiles.auth_id если null - профиль не выдавался байеру (у фарм отдела еще)
- tbl_profiles.auth_id если not null - профиль байеру выдавался. Если есть нет записей в  tbl_profile_access_grant c lock_exclusive = TRUE, то профиль у байера. Если есть - то профиль у фиксера на доработке.
- tbl_profile_access_grant если есть запись с этим profile_id и lock_exclusive = true - профиль однозначно в работе у фармера или фиксера с этим auth_id
- tbl_profile_access_grant - самая последняя запись по этому profile_id и lock_exclusive = false - это auth_id последнего фармера, работавшего с профилем. но сейчас уже профиль отпустили.
