# 📊 Схема Базы Данных `finance1_ext`

## Общая информация

Схема содержит орг структуру компании, филиалы, сотрудников из Fibery.

| Параметр | Значение |
|----------|----------|
| **Имя схемы** | `finance1_ext` |
| **Количество таблиц** | 7 базовых таблиц + пользовательские типы |
| **Тип данных ID** | UUID (универсальный уникальный идентификатор) |

---

## 📁 Таблицы схемы

### 1. **branches** — Отделения банка/организации

**Назначение:** Хранение информации о филиалах или отделениях организации с интеграцией внешних систем.

| Столбец | Тип данных | Обязательный | Значение по умолчанию | Описание |
|---------|------------|--------------|----------------------|----------|
| `id` | UUID | ✅ Да | - | Первичный ключ |
| `name` | text | ✅ Да | - | Название отделения |
| `retool_id` | text | ❌ Нет | NULL | ID в системе Retool |
| `binom_id` | text | ❌ Нет | NULL | ID в системе Binom |
| `created_at` | timestamp with time zone | ❌ Нет | now() | Дата создания записи |
| `updated_at` | timestamp with time zone | ❌ Нет | now() | Дата последнего обновления |

**Индексы:**
- `branches_pkey` — Первичный ключ (id)
- `branches_name_idx` — Индекс по полю name
- `branches_retool_id_key` — Уникальный индекс на retool_id
- `branches_binom_id_key` — Уникальный индекс на binom_id

### 3. **employees** — Сотрудники организации

**Назначение:** Основная таблица для хранения информации о сотрудниках с интеграцией внешних систем и статусом работы.

| Столбец | Тип данных | Обязательный | Значение по умолчанию | Описание |
|---------|------------|--------------|----------------------|----------|
| `id` | UUID | ✅ Да | - | Первичный ключ |
| `full_name` | text | ✅ Да | - | Полное имя сотрудника |
| `email` | text | ❌ Нет | NULL | Email адрес |
| `username` | text | ❌ Нет | NULL | Имя пользователя |
| `retool_id` | text | ❌ Нет | NULL | ID в системе Retool |
| `binom_id` | text | ❌ Нет | NULL | ID в системе Binom |
| `slack_id` | text | ❌ Нет | NULL | ID в Slack |
| `slack` | text | ✅ Да | 'Main'::text | Канал/группа Slack |
| `branch_id` | UUID | ❌ Нет | NULL | Ссылка на отделение (branches) |
| `manager_id` | UUID | ❌ Нет | NULL | Ссылка на менеджера (employees) |
| `status` | employee_status | ✅ Да | 'Работает'::employee_status | Статус работы сотрудника |
| `created_at` | timestamp with time zone | ❌ Нет | now() | Дата создания записи |
| `updated_at` | timestamp with time zone | ❌ Нет | now() | Дата последнего обновления |

**Индексы:**
- `employees_pkey` — Первичный ключ (id)
- `employees_email_uniq_idx` — Уникальный индекс на email (WHERE email IS NOT NULL)
- `employees_username_uniq_idx` — Уникальный индекс на username (WHERE username IS NOT NULL)
- `employees_retool_id_key` — Уникальный индекс на retool_id
- `employees_binom_id_key` — Уникальный индекс на binom_id
- `employees_email_fts_idx` — Full-text индекс для поиска по email
- `employees_username_fts_idx` — Full-text индекс для поиска по username

### 4. **employee_departments** — Связь сотрудник ↔ отдел (M:N)

**Назначение:** Таблица связи многих-ко-многим между сотрудниками и отделами. Один сотрудник может работать в нескольких отделах, один отдел может иметь много сотрудников.

| Столбец | Тип данных | Обязательный | Значение по умолчанию | Описание |
|---------|------------|--------------|----------------------|----------|
| `employee_id` | UUID | ✅ Да | - | Ссылка на сотрудника (employees) |
| `department_id` | UUID | ✅ Да | - | Ссылка на отдел (departments) |

**Индексы:**
- `employee_departments_pkey` — Первичный ключ (комбинированный: employee_id, department_id)
- `employee_departments_department_id_idx` — Индекс по department_id для оптимизации JOIN

## 🔧 Пользовательские типы данных

### Перечисление (ENUM)
| Тип | Описание | Значения по умолчанию |
|-----|----------|----------------------|
| `employee_status` | Статус работы сотрудника | 'Работает' |

### Composite Types (Составные типы)
Схема содержит составные типы для основных таблиц:
- `branches` — Структура записи отделения
- `departments` — Структура записи отдела
- `employees` — Структура записи сотрудника
- `groups` — Структура записи группы
- `employee_groups` — Структура связи сотрудник↔группа
- `employee_departments` — Структура связи сотрудник↔отдел
- `employee_managers` — Структура связи сотрудник↔менеджер

## 🔗 Взаимосвязи между таблицами

### Иерархия сотрудников
```
employees (id) 
    ├── employee_managers (manager_id → employees.id)
    └── employee_departments (employee_id → employees.id)
        └── departments
```

### Связь с отделами и группами
```
employees (id)
    ├── employee_departments (employee_id → employees.id, department_id → departments.id)
    │   └── departments (id)
    └── employee_groups (employee_id → employees.id, group_id → groups.id)
        └── groups (id)
```

### Вложенность отделов
```
branches (id) ←→ employees.branch_id
departments (id) ←→ employee_departments.department_id
groups (id) ←→ employee_groups.group_id
```

## 📌 Особенности реализации

1. **UUID Primary Keys** — Все таблицы используют UUID в качестве первичных ключей для распределённых систем и безопасного обмена идентификаторами.

2. **Интеграция с внешними системами:**
   - `retool_id` — Для интеграции с платформой автоматизации Retool
   - `binom_id` — Для интеграции с системой аналитики Binom

3. **Full-text поиск** — Поля `email` и `username` в таблице `employees` имеют индексы для быстрого поиска по ключевым словам.

4. **Статусы сотрудников** — Используется пользовательский тип данных `employee_status` (ENUM) для контроля допустимых значений статуса.

5. **Многие-ко-многим отношения** — Реализованы через отдельные таблицы связей:
   - `employee_departments`
   - `employee_groups`
   - `employee_managers`

6. **Timestamps с timezone** — Все временные метки хранятся с учётом часового пояса (`timestamp with time zone`).

## 💡 Рекомендации по использованию

### Для разработчиков:
- Используйте UUID для всех операций с записями
- Учитывайте наличие составных типов при формировании ответов API
- При поиске сотрудников используйте full-text индексы на email и username
- Для вложенных менеджеров требуется рекурсивный запрос через `employee_managers`

### Для аналитики данных:
- Структура позволяет строить сложные отчёты по организационной структуре
- Интеграционные поля (`retool_id`, `binom_id`) связывают данные с внешними системами
- Временные метки позволяют отслеживать историю изменений сотрудников и отделов
